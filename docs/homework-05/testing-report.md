## S03

На копии базы S02 задание доставлено в RabbitMQ после его остановки и запуска с прежним `message_id`. Проверены постоянная очередь, отсутствие маршрута и разрыв перед подтверждением публикации. Повтор при потере подтверждения может создать копию сообщения с тем же ID. [Протокол T301](protocols/s03-t301.md).

Проверены три попытки с паузами 30 и 120 секунд, оба пути доставки в очередь ошибок, повторная выдача при сбое worker, heartbeat и таймауте ack. При обрыве PostgreSQL подтверждение не отправлено, после восстановления задание продолжилось. Блокировка общего тома исключила одновременную запись двух процессов FFmpeg. В обычном Compose relay доставляет задания, а обработчик с тестовым результатом запускается отдельно на тестовом стенде. [Протокол T302–T304](protocols/s03-t302-t304.md).

Регрессия локального Compose прошла. Chrome проверил путь двух авторов до принятого видео. После запуска relay в очереди было два задания и ноль потребителей. При остановке каждой зависимости live оставался 200, ready менялся с 200 на 503 и обратно. Все 8 тестов Django прошли. [Протокол регрессии](protocols/s03-t302-t304.md#регрессия-s01-и-s02).

Регрессия T304 подтвердила, что после длительного сбоя PostgreSQL тот же worker возобновляет получение заданий. Три разрыва канала и таймаут ожидания блокировки не создали попыток. Попытку начала только действующая доставка. [Протокол](protocols/t304-recovery-regression.md).

## S04

На изолированном Compose проверены T401–T404. Штатный worker получил задания из RabbitMQ, сформировал HLS и зафиксировал READY. Четыре оригинала MP4, MOV, MKV и WebM сохранились с прежними SHA-256. Верхний портретный вариант — 720×1280, малый WebM остался 320×180.

| Задача | Фактический результат |
|---|---|
| T401 | Все четыре формата обработаны. На горизонтальном и повёрнутом портретном образцах по три качества. Малый исходник воспроизведён в одном варианте. Повреждённый исходник дал одну ошибку и сообщение DLQ. |
| T402 | Проверены падения до и после коммита, неполный HLS, обрыв связи с PostgreSQL, потеря канала, оба таймаута и живой старый FFmpeg. Неготовые файлы получили HTTP 404. Полный результат принят по manifest. READY, результат попытки и один снимок video.ready сохранены вместе. |
| T403 | Каталог и поиск по названию доступны без входа. Прямая страница, master и сегменты открываются для готового поколения. Внутренние пути, оригиналы и неактивные поколения закрыты. |
| T404 | В Chrome 157.0.8103.51, Edge 157.0.4341.46 и настольной сборке Firefox 148.0.2 прошли Auto и ручное переключение каждого доступного качества. |

Миграция 0003 прошла на пустой базе и на копии S03 с двумя заданиями. Все 9 тестов Django прошли. При остановке RabbitMQ и PostgreSQL live оставался 200, ready менялся 200 → 503 → 200. [Протокол S04](protocols/s04-hls.md).

## S05 · Переименование, частичная реализация

Самостоятельная часть T501.1 (переименование в API и кабинете) на базе S03 предварительно принята независимым review по представленным доказательствам. Весь T501, FR-008, AC-005 и S05 остаются незавершёнными. Согласована публикация проверенной части T501.1 и документации через PR; merge требует отдельного разрешения.

Результаты исходного прогона: 14 тестов Django прошли (5 новых); сборка TypeScript/Vite и браузерный сценарий Chromium прошли. На реальном PostgreSQL проверены переименование, права двух авторов, CSRF, валидация и неизменность ID, поколения, записей Upload, Job и Outbox. Django-тесты используют force_login; браузер проверяет настоящий вход и API, но видео создано напрямую в БД без физического оригинала. Ответ 503 подставлен Playwright; канал RabbitMQ в RelayTests заменён Mock. Байтовая целостность оригинала при переименовании отдельно не проверялась.

Каталог, поиск, страница просмотра, прежняя ссылка и HLS ожидают S04. Ручной повтор T501.2, удаление T502 и проверки T503 не выполнены; внешний сценарий T503 — после T602, восстановление старой БД — в T802. При текущей корректировке документации тесты не запускались. [Команды, доказательства и воспроизведение](protocols/s05-rename.md).

## Интеграция S04 и опубликованной части S05

S04 сохранён отдельным локальным коммитом 4680c9d. В рабочую ветку подготовлен merge main с PR #5 (2c451b0) без merge-коммита. Маршруты переименования и HLS объединены. Общий формат ответа сохраняет состояние текущего задания и ссылку READY. Порядковый номер запроса списка защищает кабинет от устаревшего ответа при переименовании.

Миграция прошла на чистой PostgreSQL и на копии S03 с сохранением двух видео, заданий и ID outbox. Все 15 тестов Django прошли. Дополнительные фактические результаты, особенности тестового стенда и итоговое состояние Git приведены в [протоколе интеграции](protocols/s045-integration.md).

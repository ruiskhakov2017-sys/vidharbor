# Product Spec — VidHarbor

**Статус** — Approved, версия 0.3 от 10 ноября 2026 года. База — утверждённая 0.2 с уточнениями из DEC-003.
**Объём** — новый видеосервис из ДЗ №5. Этот документ фиксирует требования к продукту и сценарии проверки.

## 1. Обзор продукта

Веб-приложение для публикации видео. Автор загружает файл из личного кабинета. Сервис сохраняет оригинал, готовит варианты качества и автоматически публикует ролик. Посетитель открывает ссылку или находит ролик по названию в общем каталоге и смотрит его прямо в приложении.

Источники требований — `Mentor_Homework_005.md`, `DZ5_New_Video_Project_Practical_Spec_RU.md` и решения пользователя в обсуждении бизнес-логики. Порядок разработки определён в `AI_Native_Engineering.md`.

## 2. Проблема

У автора есть исходный видеофайл, которым он хочет поделиться. Ему нужно один раз загрузить файл и получить страницу просмотра. Подготовка нескольких качеств и публикация происходят автоматически. Зрителю достаточно открыть страницу ролика или найти его по названию.

Это учебный продукт. Применение к записям уроков, встреч и другим роликам описывает возможный сценарий. Потребность рынка, спрос и коммерческая модель пока не подтверждены.

## 3. Пользователи и заинтересованные стороны

| Роль | Действия |
|---|---|
| Посетитель | Открывает общий каталог, ищет по названию, смотрит готовые ролики по ссылке или из каталога. Регистрация для просмотра не нужна. |
| Зарегистрированный пользователь | Получает личный кабинет. Загружает, просматривает состояние, переименовывает и удаляет свои ролики. Может повторить обработку своего ролика после временного сбоя. |
| Получатель уведомления | n8n получает уведомление о готовности и записывает данные о видео в Google Таблицу. |
| Владелец продукта и ментор | Пользователь утверждает правила продукта. Ментор задаёт обязательные ограничения учебной работы. |

## 4. Цели и признаки успеха

- Автор из своего кабинета доводит одну загрузку до готовой страницы просмотра и может поделиться ссылкой.
- Посетитель находит готовый ролик по названию и воспроизводит его без входа в аккаунт.
- Два автора управляют каждый своими роликами. Каталог и страницы просмотра общие.
- Несколько вариантов качества и ссылка для плеера реально работают. После публикации видео n8n получает уведомление, и в Google Таблице появляется запись о готовом ролике.
- При временном сбое автор может повторно запустить обработку сохранённого исходника. Неудачное задание видно и можно разобрать.

Численные цели по длительности загрузки, обработки и по одновременной нагрузке открыты. Для большого файла измеряем время и расход ресурсов в согласованной среде.

## 5. Пользовательские сценарии

1. **Публикация.** Автор регистрируется, входит, выбирает файл и указывает название. Интерфейс показывает прогресс передачи файла. После полной загрузки в кабинете появляется статус «Обрабатывается». Когда видео готово к просмотру, сервис ставит статус «Готово», добавляет его в каталог и даёт ссылку на страницу просмотра.
2. **Просмотр.** Зритель открывает ссылку или ищет ролик по названию в каталоге. На странице работает плеер с доступными качествами.
3. **Управление.** Автор переименовывает своё видео. Новое название видно в каталоге и поиске. При удалении ролик исчезает из каталога. Новые запросы по старой ссылке страницы и медиа отклоняются. Оригинал, результаты и временные файлы очищаются с безопасным повтором при сбое.
4. **Сбой передачи.** Прерванная загрузка не становится готовым исходником. Пользователь видит, что передача не завершилась. Автор начинает передачу заново. Заброшенный временный файл очищается через сутки, если передача уже не активна.
5. **Сбой обработки.** После окончательного сбоя автор видит «Не удалось обработать». Для повторяемого временного сбоя доступна кнопка «Повторить обработку». Она запускает работу с уже сохранённым оригиналом. Если исходник повреждён, приложение предлагает загрузить исправный файл. Неготовый ролик не публикуется.
6. **Уведомление о публикации.** Когда видео готово и доступно для просмотра, сервис отправляет уведомление по настроенному адресу n8n. n8n записывает название ролика, время готовности и ссылку для плеера в Google Таблицу.
7. **Сбой уведомления.** Готовый ролик остаётся доступен. Система повторяет доставку уведомления отдельно от обработки видео.

## 7. Требования к качеству и обязательные ограничения

| ID | Требование | Источник |

| NFR-001 | Отдельный продуктовый лимит по длительности не вводится. Загрузка рассчитана в том числе на исходники в несколько гигабайт. Максимум 5 ГиБ (5368709120 байт). Допускаются MP4, MOV, MKV и WebM с проверкой контейнера и потоков. Набор реально поддержанных кодеков и технические бюджеты ресурсов проверяются отдельно. | USER_APPROVED, M04 |

| NFR-003 | Повторы ограничены, неудачные задания доступны для разбора в отдельной очереди ошибок (dead-letter queue, DLQ). Сбои, дубли, перезапуск обработчика и частичные результаты учитываются. | Core M13 по контексту ментора, Q01–Q05, Q08–Q10 |

| NFR-005 | Сервис запускается через Docker Compose. Настройки окружения описаны, секреты хранятся вне репозитория, есть проверки жизни и готовности компонентов. | EXTERNAL, P01–P05 |
| NFR-006 | Наблюдение за работой включает структурированные логи, связанные ID запроса и задачи, сквозную трассу, базовые метрики и панель мониторинга. | EXTERNAL, P06–P10 |

## 9. Границы версии

Веб-продукт ограничен регистрацией и входом, личным кабинетом, публикацией, каталогом с поиском, просмотром и базовым управлением роликами. Все видео публичные. Приватность, платный доступ, подписки и рекомендации в требования первой версии не входят.

Production Practice для KazanCourts и теория Level 5 остаются отдельными частями того же ДЗ №5. Связь этого сервиса с roadmap — Project 2, Level 4, CP4 и эксплуатационная практика Level 5, CP5. Фактический прогресс по контрольным точкам подтверждается отдельно.

**Проверка бизнес-логики.** Один файл даёт одну страницу просмотра. Зрителю не нужен аккаунт или внешний сайт. Каталог получает только воспроизводимые ролики. Повтор использует сохранённый исходник. Гипотеза о ценности для реальных клиентов отделена от учебной цели.

**Проверка полноты.** Сверены M01–M13, Q01–Q10, P01–P13 и применимые F-критерии видеосервиса. Обязательные детали и доказательства по каждому пункту сохраняются в исходном ТЗ и [матрице требований](homework-05/requirements-traceability.md). Нижнюю ступень 360p пользователь выбрал для проекта. Неопределённость исходной формулировки ментора U02 сохраняется в каноническом ДЗ.

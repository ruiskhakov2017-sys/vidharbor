# S04 · Обработка и просмотр видео

**Статус** · T401–T404 выполнены локально. [Протокол S04](homework-05/protocols/s04-hls.md). Основа — `main` после S03 (`f120ac2`).

Автор загружает файл в кабинете. Штатный worker забирает задание из RabbitMQ, делает HLS из сохранённого оригинала и публикует проверенный результат. Посетитель без входа находит готовое видео по названию, открывает прямую ссылку и смотрит его в режиме Auto или выбирает качество вручную.

Выполняем задачи в порядке T401 → T402 → T403 → T404. Основание — [задачи S04](../tasks.md#s04--обработка-и-просмотр-видео), [требования и критерии приёмки](product-spec.md#8-критерии-приёмки), [архитектура](homework-05/design.md), [схема надёжности](homework-05/reliability.md) и [регрессия T304](homework-05/protocols/t304-recovery-regression.md).

## Перед началом

- **U02 · Вертикальное видео.** Пользователь утвердил рамки 360×640, 480×854 и 720×1280 для S04. После нормализации поворота и пропорций применяем те же правила уменьшения, что для горизонтали. [DEC-005](homework-05/decision-log.md#dec-005--вертикальная-рамка-и-событие-в-s04).
- Подготовить короткие образцы MP4, MOV, MKV и WebM, достаточный по размеру горизонтальный исходник, малый ролик, портретный кадр, файл с метаданными поворота, видео без звука и повреждённый образец. Записать для каждого контейнер, кодеки, размеры и ожидаемые варианты. Для портретного образца достаточного размера ожидаются три утверждённые рамки.
- Работать в ветке от актуальной `main`. Для миграций и отказов использовать отдельный Docker Compose с тестовыми секретами и томами. Проверить свободное место, память и доступность настольных Chrome, Edge и Firefox. Начать с одного процесса FFmpeg.

## T401 · Подготовка HLS из оригинала

После T204 и T304. Для вертикали применяем DEC-005.

1. Проверить закреплённую сборку FFmpeg/ffprobe в образе worker (U06). Подтвердить декодирование выбранных потоков MP4, MOV, MKV и WebM, наличие кодировщиков H.264 и AAC и работу HLS. Прогнать рабочие и повреждённые образцы, записать фактически поддержанные кодеки и причины отказов.
2. Определять размер кадра с учётом пропорций и поворота до выбора качеств. Для горизонтали использовать рамки 640×360, 854×480 и 1280×720. Вписывать кадр с сохранением пропорций без увеличения, пропускать ступени, для которых нужен upscale. Для малого исходника оставить вариант фактического размера, если ни одна ступень не подходит. Для портретного кадра использовать повёрнутые рамки.
3. Из неизменённого оригинала получить HLS VOD. Кодировать видео в H.264 и звук в AAC, если есть звуковая дорожка. Выровнять границы сегментов по ключевым кадрам для переключения качеств. Сформировать один `master.m3u8`, плейлист и сегменты для каждого фактического варианта. [Документация FFmpeg по HLS](https://ffmpeg.org/ffmpeg-formats.html#hls)
4. Сверить `ffprobe`, метаданные HLS и размеры полученных файлов. Проверить три качества на достаточном горизонтальном исходнике, меньший набор на малом, корректный поворот и портретную лестницу по DEC-005. Проверить воспроизведение образца без звука и сохранность SHA-256 оригинала.

## T402 · Штатный worker и безопасная публикация

После T103 и T401. Используем outbox, историю попыток, паузу подписки при сбое PostgreSQL и блокировку T304.

1. Подключить штатный worker к Docker Compose. Сохранять номер попытки перед запуском FFmpeg. Ограничить ресурсы, параллельность и время процесса. Кандидат из схемы надёжности — до 3 часов на попытку при таймауте `ack` в 4 часа. На стенде проверить короткий таймаут, остановку группы FFmpeg при потере канала или отзыве поколения и наследование файловой блокировки пишущим процессом. Если потомок ещё жив, его блокировка продолжает защищать папку. Неподдерживаемый формат завершает работу с причиной, временный сбой использует повторы S03.
2. Под одной блокировкой писать в единственную закрытую папку `processing` для видео. Проверить завершённость HLS, наличие всех ссылок из плейлистов и отсутствие посторонних путей. Сохранить manifest с ID задания, поколением, списком и SHA-256 файлов. Синхронизировать файлы и каталог перед публикацией. Предусмотреть переименование `processing` в каталог готового поколения на том же томе без перезаписи.
3. В короткой транзакции заблокировать строку видео, проверить актуальность поколения и отсутствие удаления, затем переименовать каталог на том же томе и зафиксировать активный результат, `Video.READY`, успешный исход задания и одно событие `video.ready` для будущей доставки в S06. Отправить ручной `ack` после коммита. Проверить миграции на пустой базе и копии S03 с ожидающим заданием. Загрузить короткий ролик через обычный API и довести его до `READY` через реальную очередь.
4. Восстанавливать публикацию под той же файловой блокировкой. Если worker упал после переименования и до коммита, сначала сверить manifest и хэши и принять полный результат действующего поколения без второго FFmpeg. Проверку выполнять до того, как механизм S03 запишет потерю попытки и назначит повтор. Неполный, повреждённый или устаревший результат оставлять закрытым и обрабатывать по правилам восстановления. Дубль после коммита подтверждать без нового запуска и нового события.
5. Вызвать сбои на реальном томе и сверить БД, хэши файлов и доставки RabbitMQ. Остановить worker во время записи при живом FFmpeg, после переименования до коммита и после коммита до `ack`. Проверить, что второй процесс не пишет в занятую папку, успешный результат один, а испорченные и устаревшие файлы закрыты. Повторить проверку потери канала, таймаута и восстановления после сбоя БД на пути реальной публикации.

## T403 · Каталог, поиск и страница просмотра

После T402.

1. Добавить публичный каталог с поиском по названию без учёта регистра и прямую страницу просмотра по стабильному ID. Каталог и прямой маршрут открываются без входа для `READY`. В кабинете своего ролика показать «Обрабатывается», «Готово» со ссылкой или «Не удалось обработать». Проверить переходы на загруженном ролике и доступ гостя из нового сеанса.
2. Разрешать каждый запрос `master.m3u8`, плейлиста варианта и сегмента только для активного готового поколения. Передавать разрешённый файл Nginx через внутренний маршрут. Главная ссылка остаётся стабильной, а пути вариантов и сегментов относятся к опубликованному поколению. Проверить MIME, относительные ссылки, отсутствие долгого кеша и невозможность обращения к оригиналу, `processing`, устаревшему поколению и внутреннему URL. Связать HTTP-проверки закрытой выдачи с отказами из T402. [Документация Nginx о внутренних маршрутах](https://nginx.org/en/docs/http/ngx_http_core_module.html#internal)
3. Подключить hls.js с закреплением версии в lockfile. Плеер открывает одну ссылку `master.m3u8`, отличную от ссылки на страницу. Меню строится по фактическим уровням из плейлиста. Проверить старт просмотра, прямой вход на страницу и понятное сообщение при ошибке воспроизведения. [API hls.js](https://github.com/video-dev/hls.js/blob/master/docs/API.md)

## T404 · Проверка качеств и браузеров

После T403.

1. На исходнике достаточного размера проверить 360p, 480p и 720p. Сверить плейлист, фактические размеры и текущий уровень плеера. Переключить каждое доступное качество вручную во время просмотра и вернуться в Auto. Для Auto подтвердить автоматический режим, а для ручного выбора — получение сегментов выбранного варианта.
2. На малом и вертикальном образцах сверить ожидаемый набор с плейлистом и меню. Подтвердить отсутствие увеличенных вариантов, правильную ориентацию и воспроизведение каждого доступного качества. Записать решение U02 рядом с результатом вертикальной проверки.
3. Повторить проверки в настольных Chrome, Edge и Firefox. Для каждого записать версию, образец, качества и итог. В отдельном сеансе без входа проверить поиск, прямую ссылку и загрузку плейлиста с сегментами. Для неготового или ошибочного видео подтвердить отсутствие в каталоге и отказ прямых запросов.

|---|---|
